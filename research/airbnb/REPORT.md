# تحلیل Airbnb — ۲۰۲۶-۱۰-۲۰
> روش: خواندن زندهٔ airbnb.com، تحلیل UX نوار جستجو و Date Picker، مستندات Flexible Dates و کامپوننت متن‌باز HorizonCalendar خود Airbnb.
> چرا برای ما: نزدیک‌ترین محصول جهان به «تقویم + انتخاب تاریخ» دست‌افزار.

## ۱) فلسفه
1. **جستجو خودِ محصول است:** صفحهٔ اصلی یک نوار است (Where / When / Who) — کاربر قبل از هر توضیحی دارد کار اصلی را انجام می‌دهد.
2. **تاریخ، «داده» نیست «تصمیم» است:** دو تب Dates و Flexible؛ یعنی اول می‌پرسد «تاریخت قطعی است یا منعطف؟» بعد ابزار مناسب می‌دهد.
3. **اعتماد در خود کارت است:** روی هر اقامتگاه: امتیاز (۴٫۹۹)، نشان Guest Favorite، قیمت شفاف «برای ۲ شب» — هیچ عددی پنهان نیست.
4. **عکس واقعی، نه تصویرسازی:** محتوا خودش هیرو است؛ UI عقب می‌ایستد.

## ۲) آناتومی نوار جستجو و تقویم (مهم‌ترین بخش برای ما)
- نوار یکپارچهٔ پیل‌شکل، تقسیم‌شده با خط مویی (hairline)؛ هر فیلد لیبل کوچک بالا + مقدار/placeholder پایین؛ دکمهٔ جستجوی دایره‌ای در انتها.
- کلیک روی هر فیلد → پنل همان فیلد دقیقاً زیر خودش باز می‌شود؛ فوکوس خودکار به فیلد بعدی می‌رود (انتخاب مقصد → تقویم باز).
- تقویم **دو ماه کنار هم** (دسکتاپ)؛ روز انتخابی دایرهٔ مشکی پر، بازه بین دو روز نوار خاکستری پیوسته (lozenge) — وضعیت‌ها: default / hover / selected-start / selected-end / in-range / disabled.
- زیر تقویم: چیپ‌های «تاریخ دقیق یا ±۱/۲/۳/۷/۱۴ روز» — انعطاف به‌صورت عدد، نه متن مبهم.
- تب Flexible: جستجو با «آخر هفته / یک هفته / یک ماه» بدون تاریخ قطعی.
- رفتارهای لبه (از تحلیل state machine پیکرشان): کلیک قبل از شروع = شروع تازه (نه جابه‌جایی ساکت)؛ کلیک سوم = ری‌استارت انتخاب؛ هاور فقط «پیش‌نمایش» بازه است، حقیقت ذخیره‌شده نیست؛ Escape و کلیک بیرون = لغو.
- واحد روز ۴۰×۴۰px دایره‌ای؛ مدل داده «تاریخ تقویمی» (ISO string) است نه timestamp — درس مستقیم برای جلالی ما: تاریخ را رشته/سه‌تایی نگه دار، نه Date میلادیِ نیمه‌شب.

## ۳) HorizonCalendar (سند مهندسی خودشان)
کتابخانهٔ تقویم متن‌باز Airbnb: چیدمان عمودی/افقی ماه‌ها، پشتیبانی رسمی RTL، اسکرول مجازی برای بازه‌های بزرگ، آپدیت انیمیشنی. پیامش: تقویم محصولِ جدی، کامپوننت جدی می‌خواهد — state تک‌جهته و declarative.

## ۴) چی را می‌دزدیم (الگو، نه کپی) — نقشهٔ دست‌افزار
| الگوی Airbnb | اعمال در دست‌افزار |
|---|---|
| جستجو = خود محصول | هیروی ما مبدل زنده دارد (داریم ✓) — همین منطق: هر ابزار، ورودی‌اش بالاست نه توضیحش |
| فیلد چندبخشی با لیبل کوچک داخل فیلد | مبدل تاریخ: سه فیلد روز/ماه/سال با لیبل داخلی، فوکوس خودکار بعدی بعد از تکمیل (احتیاط: درس فوکوس v0.6.1) |
| وضعیت‌های کامل روز تقویم | تقویم ما: امروز/انتخابی/تعطیل/مناسبت‌دار/جمعه — ماتریس وضعیت مکتوب و جدا (داریم، کامل‌تر شود) |
| «منعطف» به‌جای تاریخ قطعی | در اختلاف دو تاریخ و شمارش نوروز: چیپ‌های آماده «امروز»، «اول ماه»، «نوروز» به‌جای تایپ دستی |
| قیمت/عدد شفاف روی کارت | کارت نتیجه: عدد اصلی + واحد + معادل — بدون عدد پنهان (داریم ✓، نگهش دار) |
| کلیک سوم = ری‌استارت ساکت و قابل پیش‌بینی | در انتخاب بازه/روز: رفتار لبه‌ها باید تعریف‌شده و یکدست باشد، نه اتفاقی |

## ۵) نقد صادقانه — چه چیز را نمی‌گیریم
- Airbnb مارکت‌پلیس است؛ تراکم کارت و عکس برای جعبه‌ابزار ما زیادی است — UI باید عقب‌تر بایستد.
- پیکر رزرو (پرداخت، مهمان، قانون کنسلی) به ما ربطی ندارد؛ فقط لایهٔ «انتخاب تاریخ» را می‌گیریم.
- جستجوی AI جدیدشان برای ابزار دقیق ما ضدالگوست: کاربر ما عدد قطعی می‌خواهد، نه حدس مدل.
