# تحلیل Linear — ۲۰۲۶-۱۰-۲۰
> روش: خواندن زندهٔ linear.app، تحلیل‌های فنی معماری سرعت (local-first)، مستندات ریدیزاین UI خود Linear و بررسی Design System آن.
> چرا برای ما: مرجع جهانی «سرعت + تراکم + میکرواینترکشنِ بی‌صدا» — دقیقاً چیزی که ممیزی تعامل v0.6.1 ما دنبالش است.

## ۱) فلسفه
1. **سرعت، ویژگی نیست؛ زبان طراحی است:** لود زیر ۲۰۰ms، ترنزیشن زیر ۱۰۰ms هدف طراحی است نه نتیجهٔ اتفاقی مهندسی.
2. **محصول خودش دمو است:** هیرو اسکرین‌شات مرده نیست؛ UI واقعی محصول در حال کار (ایجنت ایشو برمی‌دارد، PR ساخته می‌شود).
3. **کیبورد اول، موس دوستانه:** هر اکشن میانبر دارد؛ ⌘K پالت فرمان برای همه‌چیز — ولی موس‌کار هم هیچ‌جا گیر نمی‌کند.
4. **سکوت بصری:** پالت خنثی + یک رنگ تاکیدی؛ سلسله‌مراتب با تایپوگرافی و فاصله، نه با قاب و سایهٔ زیاد.

## ۲) آناتومی سرعت (معماری، نه ترفند CSS)
- **Local-first:** داده در مرورگر (IndexedDB + MobX)؛ UI از حافظه رندر می‌شود، سینک در پس‌زمینه — اسپینر وجود ندارد چون انتظاری وجود ندارد.
- **Optimistic UI:** تغییر اول روی صفحه اعمال می‌شود، بعد ذخیره؛ آپدیت ۵۰ آیتم = ۵۰ رندر سلولی، نه رندر کل لیست (granular observables).
- **Service Worker:** ناوبری بعدی بدون شبکه؛ آفلاین هم کار می‌کند.
- **حرکت GPU-only:** فقط transform/opacity انیمیت می‌شوند؛ layout-property هرگز. مدت‌ها: میکرو ۱۰۰ms، استاندارد ۱۵۰ms، صفحه ۲۵۰ms با ease-out ‏(0.16,1,0.3,1).
- **پالت فرمان به‌مثابه معماری:** جستجو روی دادهٔ لوکال است، برای همین آنی است — پالت کند، پالت مرده است.

## ۳) سیستم طراحی (اعداد قابل دزدیدن)
- ریتم تراکم یکدست: ردیف‌ها ۳۲/۴۰px در همهٔ لیست‌ها و جدول‌ها — «تراکم‌های کمتر، استفادهٔ منظم‌تر».
- اعداد tabular در جدول‌ها، مدت‌ها جمله‌ای («۲ هفته پیش» نه «2w»)، sentence-case.
- Empty State: یک جمله + خط مویی؛ بدون متن بازاریابی و التماس.
- هاور: لیفت ۱–۲px و سایهٔ خیلی خفیف؛ active: اسکیل ۰٫۹۷ — بازخورد لمسی بدون نمایش.
- میانبرها mnemonic و قابل کشف‌اند: کنار هر اکشن در هاور دیده می‌شوند (C بساز، S وضعیت…) — کیبورد را «یاد می‌دهد» نه اینکه فرض کند بلدی.

## ۴) چی را می‌دزدیم — نقشهٔ دست‌افزار
| الگوی Linear | اعمال در دست‌افزار |
|---|---|
| محاسبهٔ لوکال = سرعتِ حس‌شده | محاسبات ما همین حالا روی دستگاه است ✓ — این را به زبان کاربر هم بگو («نتیجه فوری» نوار اعتماد) |
| حرکت فقط transform/opacity، سقف ۲۵۰ms | تقویم ما ۲۴۰ms دارد ✓ — قانون شود: هیچ انیمیشن layout (width/height) در محصول |
| active:scale .97 | دکمه‌ها و روزهای تقویم: بازخورد فشردن یکدست |
| فوکوس خودکارِ مرحله‌ای در فلوی چندفیلدی | فرم‌های جلالی: بعد از روز کامل → ماه → سال (با گارد remount v0.6.1) |
| ⌘K / پالت فرمان | صفحهٔ ابزارها: جستجوی کیبوردی سریع ابزارها (فاز بعد؛ جستجوی فعلی پایه است) |
| ریتم تراکم واحد | لیست مناسبت‌ها/ابزارها/داشبورد: ارتفاع ردیف و گپ از یک توکن |
| Empty State یک‌جمله‌ای | حالت خالی جستجوی ابزارها و داشبورد — کوتاه، بدون عذرخواهی |

## ۵) نقد صادقانه — چه چیز را نمی‌گیریم
- Linear ابزار B2B برای پاوريوزر است؛ تراکم و میانبرمحوری‌اش برای کاربر عمومی فارسی‌زبان (موبایل، لمسی، گاه‌به‌گاه) زیادی است — «سکوت و سرعت» را می‌گیریم، «تراکم و کیبورد» را نه.
- تم تیرهٔ پیش‌فرض و تک‌رنگ بنفش با برند سبز ما نمی‌خواند.
- Local-first سینک برای ابزار بی‌سرور ما موضوعیت ندارد؛ اصلش را می‌گیریم: «اول رندر کن، بعد هر کاری».
