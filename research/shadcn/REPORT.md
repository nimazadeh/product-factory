# تحلیل shadcn/ui — ۲۰۲۶-۱۰-۲۰

> روش: خواندن زندهٔ داک رسمی (ui.shadcn.com)، سورس واقعی کامپوننت در GitHub، اسکرین‌شات زنده و اندازه‌گیری Computed Style از صفحهٔ Button.

## ۱) فلسفه — چرا shadcn «پریمیوم» حس می‌شود؟

shadcn کتابخانه نیست؛ **کد کامپوننت را می‌دهد دست خودت** (copy-own). حس پریمیوم از این‌ها می‌آید:

1. **خنثی بودن افراطی:** پیش‌فرض تقریباً سیاه/سفید/خاکستری است. رنگ فقط وقتی معنا دارد می‌آید. مغز کاربر این را «تمیز و گرون» می‌خواند.
2. **توکن، نه عدد تصادفی:** همه‌چیز از CSS Variable می‌آید (`--background`, `--primary`, `--radius`, `--card-spacing`). برای همین ۶۶ کامپوننت کنار هم «یک خانواده» حس می‌شوند.
3. **تراکم کم، ریتم ثابت:** فاصله‌ها از یک متغیر مشترک (`--card-spacing`: شانزده/۲۰/۲۴/۳۲px) تغذیه می‌شوند.
4. **حالت‌ها کامل‌اند:** برای هر کامپوننت hover/focus/disabled/invalid/loading از روز اول تعریف شده. پریمیوم = هیچ حالتی «فراموش» نشده.
5. **دسترس‌پذیری نامرئی:** روی Radix/Base UI سوار است — فوکوس، کیبورد، ARIA درست، بدون اینکه دیده شود.

## ۳) آناتومی سه کامپوننت کلیدی (از داک + سورس واقعی)

### Button
- API: ‏`variant` شش‌تایی (default/outline/secondary/ghost/destructive/link) × ‏`size` هشت‌تایی (xs تا icon-lg) — **۹۰٪ نیاز هر محصول با همین ماتریس پوشش داده می‌شود**
- اندازه‌گیری زنده از سایت خودش: ارتفاع دکمه‌ها ۲۸–۳۶px، شعاع ۸–۱۰px، فونت ۱۴px وزن ۵۰۰ — یعنی **کوچک‌تر و ساکت‌تر از چیزی که ما می‌سازیم** (دکمه‌های ما ۴۸px و فریادزن‌اند؛ در موبایل لمسی لازم است، در دسکتاپ نه)
- جزئیات پولیش: ‏`disabled:opacity-50` + قطع pointer-event، آیکن‌ها `pointer-events-none` و shrink-0، ترنزیشن روی «همه‌چیز»، انتخاب متن خاموش
- قانون طلایی از داک: لینک نباید نقش دکمه بگیرد — برای لینک از `buttonVariants` روی ‏`<a>` استفاده کن (سمانتیک تمیز)

### Card
- ترکیب ثابت: Card → Header (Title + Description + Action) → Content → Footer
- **`--card-spacing`**: یک متغیر، فاصلهٔ همه بخش‌ها را کنترل می‌کند (پیش‌فرض ۲۴، sm ‏۱۶) — این دقیقاً چیزی است که کارت‌های ما ندارند؛ هر کارت ما پدینگ خودش را دارد
- ترفند حرفه‌ای: محتوای لبه‌به‌لبه با حاشیه منفی هم‌اندازهٔ همان متغیر، تا تراز اینست کارت حفظ شود

### Input / Field
- فرم از «فیلد» ساخته می‌شود نه اینپوت تنها: Label + Input + Description + خطا، با `data-invalid`/`aria-invalid` — خطا جزئی از کامپوننت است نه اتفاق بعد از آن
- حالت‌ها: disabled روی کل فیلد کم‌رنگ می‌شود، invalid رنگ + ARIA هم‌زمان

## ۴) سیستم توکن (از صفحه Theming)

رنگ‌ها معنایی‌اند نه ظاهری: background/foreground، card، popover، primary، secondary، muted، accent، destructive، border، input، ring + شعاع پایه `--radius` که از آن sm/md/lg/xl مشتق می‌شود. حالت تاریک با همان توکن‌ها و مقادیر دیگر (OKLCH). **درس:** ما در دست‌افزار رنگ خام (#0B6B4F) پخش کرده‌ایم؛ باید لایهٔ معنایی بسازیم.

## ۵) RTL — خبر خوب

shadcn حالا پشتیبانی رسمی RTL دارد: CLI کلاس‌های فیزیکی (left/right) را به منطقی (start/end) تبدیل می‌کند، آیکن‌های جهتی را می‌چرخاند و برای Calendar/Pagination/Sidebar راهنمای دستی دارد. یعنی اگر روزی به shadcn مهاجرت کنیم، فارسی بودن ما مانع نیست.

## ۶) چی را می‌دزدیم (الگو، نه کپی) — نقشه پولیش دست‌افزار

| الگوی shadcn | اعمال در دست‌افزار |
|---|---|
| توکن معنایی + `--radius` واحد | بازنویسی متغیرهای globals.css: ‏surface/ink/muted/border/ring + شعاع‌های مشتق |
| `--card-spacing` واحد | پدینگ همه کارت‌ها (ابزار، مناسبت، آمار ادمین) از یک متغیر |
| ماتریس variant×size دکمه | کلاس‌های ‎.btn با variant (primary/ghost/outline) و size (sm/md/lg) — پایان دکمه‌های تک‌نسخه |
| Field کامل (لیبل+توضیح+خطا) | فرم مبدل و فاکتورساز آینده: خطا زیر فیلد با ARIA، نه فقط پیام کلی |
| حالت‌های کامل | برای هر تعاملی: hover/focus-visible/active/disabled/loading از روز اول |
| تراکم ساکت دسکتاپ | دکمه دسکتاپ ≤۴۰px، مینیمم ۴۴px فقط لمسیِ موبایل |
| فوکوس رینگ استاندارد | ‏`:focus-visible` یکدست سراسری (الان هر کامپوننت راه خودش را می‌رود) |
| Skeleton و Empty | داشبورد ادمین و لیست ابزارها: حالت خالی و بارگذاری طراحی‌شده |

## ۷) نقد صادقانه — shadcn همه‌چیز نیست

- پیش‌فرض عمداً «بی‌روح» است؛ برند ما به رنگ و شخصیت نیاز دارد (تمیز بودن را می‌گیریم، خنثی بودن کامل را نه)
- روی Tailwind بنا شده؛ دست‌افزار CSS خام دارد — مهاجرت کامل هزینه‌بر است؛ **توکن و الگو را می‌آوریم، فریم‌ورک را نه** (تصمیم قابل بازبینی هنگام فاکتورساز)
- کامپوننت‌ها LTR-first طراحی شده‌اند؛ در RTL جزئیات تقویم و سایدبار دستی نیاز به مراقبت دارند
