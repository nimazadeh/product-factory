# Skill 22 — Premium Polish System (shadcn/ui الگوی مرجع)

> منبع: تحلیل زندهٔ shadcn/ui در ۲۰۲۶-۱۰-۲۰ — گزارش کامل: `research/shadcn/REPORT.md`
> هدف: رساندن خروجی به حس «پریمیوم» با سیستم، نه سلیقه. این skill روی همهٔ skillهای قبلی سوار می‌شود و قبل از تحویل هر UI اجرا می‌شود.

## اصل بنیادین

پریمیوم = **توکن معنایی + ریتم ثابت + حالت‌های کامل + سکوت بصری**.
رنگ و اندازه هرگز خام و پراکنده در کامپوننت‌ها نوشته نمی‌شوند؛ از لایهٔ توکن می‌آیند.

## ۱) لایهٔ توکن (اجباری برای هر محصول)

```css
:root{
  /* معنایی، نه ظاهری */
  --background: ...;  --surface: ...;
  --ink: ...;         /* متن اصلی */
  --ink-muted: ...;   /* متن فرعی — فقط یک سطح */
  --border: ...;      --ring: var(--primary);
  --primary: ...;     --primary-ink: ...;
  --destructive: ...;
  /* شعاع: یک پایه، بقیه مشتق */
  --radius: 12px;
  --radius-sm: calc(var(--radius) - 4px);
  --radius-lg: calc(var(--radius) + 4px);
  /* فاصلهٔ کارت: یک متغیر برای همهٔ کارت‌ها (الگوی ‎--card-spacing شادکن) */
  --card-spacing: 20px;
  /* حرکت (از skill 19) */
  --ease-out: cubic-bezier(.22,1,.36,1);
}
```

قوانین:
- هیچ `#[hex]` تازه‌ای داخل کامپوننت نیاید؛ اول توکن بساز.
- متن فرعی فقط `--ink-muted` — خاکستری سوم اختراع نکن.
- سایه فقط دو سطح: `shadow-sm` برای کارت، `shadow-lg` برای لایهٔ شناور. سایهٔ سوم = بی‌نظمی.

## ۲) ماتریس کامپوننت (الگوی Button شادکن)

هر کامپوننت تعاملی با دو محور ساخته می‌شود:
- **variant:** ‏primary / outline / ghost / destructive / link
- **size:** ‏sm (۳۶) / md (۴۴ لمسی، ۴۰ دسکتاپ) / lg (۴۸) / icon

و هر کامپوننت از روز اول این حالت‌ها را دارد — ناقص = تحویل ممنوع:
`default · hover · focus-visible (رینگ ‎--ring) · active (scale .98) · disabled (opacity .5 + بدون رویداد) · loading`

- لینک هرگز نقش دکمه نمی‌گیرد؛ ظاهر دکمه روی `<a>` با همان کلاس variant.
- آیکن داخل دکمه: `pointer-events:none`، اندازه ثابت ۱۶–۱۸، فاصله از متن ۶–۸.

## ۳) فرم = Field، نه Input تنها (الگوی Field شادکن)

```
Label → Input → Description (راهنما) → Error (زیر فیلد، با aria-invalid)
```
- خطا زیر همان فیلد با رنگ destructive + `aria-invalid="true"`؛ پیام کلی بالای فرم فقط مکمل است.
- فیلد disabled کل گروه را کم‌رنگ می‌کند، نه فقط اینپوت را.
- لیبل همیشه بالای فیلد و وسط‌چین نسبت به اینپوت (ممیزی هندسی skill 21).

## ۴) ریتم فاصله و تراکم

- همهٔ فاصله‌ها مضرب ۴: ‏۴/۸/۱۲/۱۶/۲۴/۳۲/۴۸ — عدد ۱۵ یا ۲۲ ممنوع.
- پدینگ کارت فقط از `--card-spacing`؛ کارت کوچک = همان متغیر کمتر، نه عدد تازه.
- دسکتاپ «ساکت» است: دکمه ≤۴۰px، فونت بدنه ۱۴–۱۵. مینیمم لمسی ۴۴px فقط موبایل/تاچ.
- فضای خالی لوکس است؛ هر بخش یک پیام. تراکم دیجی‌کالایی فقط برای ریل فروشگاهی.

## ۵) تایپوگرافی

- سه سطح بیشتر نه: تیتر (وزن ۸۰۰)، بدنه (۴۰۰)، فرعی (muted، یک پله کوچک‌تر).
- ارتفاع خط فارسی: تیتر ۱.۳–۱.۴۵، بدنه ۱.۸–۱.۹.
- اعداد در داده/شمارش: هم‌عرض (tabular) تا هنگام تغییر نلرزند.

## ۶) گیت پولیش (قبل از اعلام «تمام شد» — همه باید سبز باشند)

1. اسکرین‌شات موبایل ‎۳۹۰ و دسکتاپ ‎۱۴۴۰ + نگاه در زوم ۲۰۰٪ روی هیرو و یک کارت.
2. overflow افقی = ۰؛ هیچ المانی از کادر بیرون نیست (bounding box تک‌تک).
3. هیچ رنگ/شعاع/فاصلهٔ خارج از توکن در کد تازه نیست (grep روی hex).
4. تب‌گردانی با کیبورد: فوکوس رینگ روی همهٔ تعاملی‌ها دیده می‌شود.
5. حالت خالی و بارگذاری (Empty/Skeleton) برای هر لیست/داده‌ای وجود دارد.
6. حرکت‌ها ۱۵۰–۳۰۰ms با ‎--ease-out؛ ‏prefers-reduced-motion رعایت شده.
7. تست سفیدی اسکرین‌شات (اسکرین‌شات خالی = نامعتبر).

## ۷) چی از shadcn نمی‌گیریم

- خنثیِ کامل و بی‌رنگی — برند ما رنگ و شخصیت دارد؛ سکوت را می‌گیریم، بی‌روحی را نه.
- Tailwind اجباری نیست؛ توکن و الگو مستقل از فریم‌ورک‌اند.
- در RTL: تقویم/سایدبار/پاپ‌آور نیازمند ممیزی دستی‌اند (راهنمای RTL خود شادکن هم همین را می‌گوید).

## چک‌لیست یک‌خطی برای هر صفحه

توکن؟ ماتریس variant/size؟ حالت‌های کامل؟ Field درست؟ ریتم ۴؟ فوکوس؟ Empty/Skeleton؟ اسکرین‌شات دو سایز + زوم ۲۰۰٪؟

## ۸) ممیزی تعامل (درس باگ فوکوس — ۲۰۲۶-۱۰-۲۰، اجباری)

> باگ واقعی دست‌افزار: کامپوننت فیلد داخل کامپوننت پدر تعریف شده بود؛ با هر
> رندر remount می‌شد و فوکوس بعد از رقم اول می‌پرید. همهٔ تست‌ها سبز بودند چون
> با `fill()` تست شده بود، نه تایپ انسانی. اسکرین‌شات هم این باگ را نشان نمی‌دهد.

قوانین:
- **کامپوننت تو‌در‌تو تعریف نکن** — کامپوننت داخل بدنهٔ کامپوننت دیگر = remount در هر رندر = از دست رفتن فوکوس/state داخلی. کامپوننت‌ها فقط سطح ماژول.
- تست فرم‌ها فقط با `keyboard.type` رقم‌به‌رقم (و ارقام فارسی) + assert روی `toBeFocused()` بعد از آخرین رقم؛ `fill()` فقط برای setup مجاز است، نه به‌عنوان تست تعامل.
- مسیر کامل دست کاربر تست شود: کلیک → تایپ ترتیبی → Tab بین فیلدها → Enter/Submit → خطای عمدی → اصلاح.
- هر فیلد stateful (جستجو، OTP، تاریخ چندبخشی) یک تست «ماندن فوکوس حین تایپ» می‌خواهد.
